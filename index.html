纯前端解析与下载，导出启动器可直接使用的 .minecraft 压缩包

运行方式

页面本身不发起任何服务端下载。清单解析、分片下载、哈希校验与 ZIP 封包全部在浏览器内完成，可保存到本地文件或 OPFS 暂存后下载。

    流程

    1. 解析清单 版本清单 → 版本 JSON → 库/资源索引/日志配置，对应 HMCL 的 GameBuilder 流程
    2. 构建计划 规则过滤、natives 分类器、加载器补丁合并、整合包清单展开
    3. 预排布 ZIP 按已知大小计算本地文件头偏移，数据区可被任意顺序写入
    4. 分片下载 文件内 Range 分片 + 跨文件并发，分片 CRC 在 Worker 的 WASM 内计算
    5. 顺序校验 分片按序落盘并串行喂给 SHA-1，与清单哈希比对
    6. 封包 补写 CRC、中央目录，必要时写 ZIP64 记录

    导出选项

    分片下载 = 同一个文件拆成多个 Range 请求，慢速链路更快，但部分站点会判定为异常流量（人机验证/限流），默认关闭。关闭时每个文件只发一条连接，文件之间仍然按“并发连接”并行。并发按 HTTP/2 多路复用设计：同一主机的请求跑在一条连接的多个流上，上限用「HTTP/2 每主机流」（默认 32）；浏览器不能指定 HTTP 版本、也读不到协商结果，所以该主机连续失败 2 次就自动回退到 HTTP/1.1 的「每主机连接」（默认 6）。

    下载源

    默认网关 https://mc-gateway.noon.pw/api/gw?url={url}（EdgeOne 部署），可换成自建实例；留空即不用网关。网关只收发不返回 Access-Control-Allow-Origin 的上游：官方 libraries / resources / launcher(meta).mojang.com，以及当前选中镜像站的根（BMCLAPI 与各高校镜像都不带 ACAO）；自带 CORS 的主机一律直连。镜像站点只换镜像根的运营方：BMCLAPI 覆盖全部资源，高校镜像只镜像 maven 子树。镜像站不可达时自动落到库代理 repo.spongepowered.org/repository/maven-public/ 与源站（同一主机连续 3 次失败即熔断，本次会话内不再排它）。
    若用带 --disable-web-security --user-data-dir=C:\tmp 参数单独启动的 Chrome 打开本页，勾选「无 CORS 限制」：所有上游都直连（官方 libraries / resources、BMCLAPI、高校镜像），不再经过网关。该开关默认关闭，只对这一个浏览器实例生效；关掉同源策略的实例不要用来登录其他网站。

    能力边界

    • 原版：版本 JSON、客户端 jar、运行库、资源索引与资源对象、日志配置全部可下载
    • Fabric / Quilt / Legacy Fabric：按加载器 profile JSON 合并库与主类，全部可下载
    • Forge / NeoForge：可解析安装器内的版本补丁与库；安装器声明的 processor 需要 JVM，浏览器无法执行，导出报告中会逐项列出
    • 整合包：Modrinth 完整；CurseForge 需要清单内含 fileName；MCBBS 的 addons 需要按项目 ID 解析，未展开时列入报告

    文件排列（版本隔离）

    .minecraft/
  assets/indexes/<id>.json
  assets/objects/<前两位>/<hash>
  assets/log_configs/<id>
  libraries/<maven 路径>
  versions/<实例ID>/<实例ID>.json
  versions/<实例ID>/<实例ID>.jar
  versions/<实例ID>/mods|config|saves|resourcepacks/...

    实例的游戏目录落在 versions/<实例ID>/ 下，等价于 HMCL 开启版本隔离后的布局。
